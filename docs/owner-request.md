# 本人要望メモ

## 1. 参照元

- 画像資料: `docs/本人要望.jpg`
- この画像は、秩序めあ本人が求める Web サイトの方向性を示す要望資料として扱う

## 2. 今回の解釈

ユーザーから共有された意図は次のとおり。

- 画像の左側は、本人が求めているサイトのレイアウト案
- 画像の右側は、サイト内に書きたい内容の案
- 作業者にはかなり大きい裁量がある
- 単なる再現よりも、完成度の高いサイトに仕上げることを優先してよい
- 必要であれば、画像に直接書かれていない機能や導線を追加してよい

## 2.1 新しい画像から読み取れたこと

新しく置き直された `本人要望.jpg` をもとに、少なくとも次の意図は維持されていると判断する。

- 左側に「求めるレイアウト」のイメージがある
- 右側に「いま書きたい内容」のメモがある
- 本人の希望はあるが、作業者側で再構成や強化を行ってよい

## 2.2 画像から比較的確度高く拾えた項目

OCR と全体の文脈から、次のような項目は本人要望に含まれている可能性が高い。

- イラストまたは立ち絵を大きく見せること
- プロフィール情報をまとめること
- 日付系の基本情報を載せること
- ママ表記を載せること
- タグ類を載せること
- 好きなもの欄を載せること

補足:

- ユーザー補足により、`とりうら` さんは活動において使用している立ち絵を作ってもらった人であり、VTuber / Vライバーとしてのママであることが確定
- タグやプロフィール項目も存在している可能性が高いが、文言の正確な転記は未確定

## 2.3 レイアウトとしての解釈

新しい画像からは、次のようなレイアウト要望として解釈するのが自然。

- ビジュアルを主役にする
- その周囲または隣にプロフィール情報を置く
- 情報はカードやまとまり単位で見せる
- 「書きたいこと」は単なる箇条書きではなく、サイトの各セクションへ分配して整理する

## 2.4 実装に落とし込むときの判断

画像右側のメモは、そのまま 1 つの文章として載せるのではなく、次のようなセクションに分解して扱う。

- Hero
- Profile / About
- Tags
- Likes
- Visual / Illustration credit
- Update / Diary
- SNS / Links
- Guideline / Contact

## 3. 実装判断の前提

この資料は「厳密な完成見本」ではなく、方向性を示すラフ要望として扱う。

- 画像の構成や空気感は尊重する
- ただし pixel-perfect な再現を最優先にはしない
- PC だけでなく、スマホでも成立する構成へ再解釈してよい
- 情報の見やすさ、導線、更新しやすさ、サイトとしての完成度を優先する

## 4. デザイン方針として採用すること

- 本人要望のレイアウト感をベースにする
- 右側の「書きたいこと」を、実際のセクション構成へ落とし込む
- サイト全体として統一感のあるデザインに整える
- 仮置きの内容でも、あとから差し替えやすい構造で作る

## 5. 作業者に許可されている拡張

本人要望を満たしつつ、次のような追加や改善を行ってよい。

- ナビゲーションの追加
- Hero セクションの強化
- プロフィールや基本情報の整理
- 更新情報 / 日記 / お知らせ欄の追加
- SNS 導線の整理
- ガイドライン / Contact 導線の追加
- ビジュアルやギャラリー系セクションの追加
- レスポンシブ対応の最適化
- アクセシビリティ改善
- モーションや装飾の調整

## 6. 実装優先順位

現時点では、次の順番で仕上げるのが自然。

1. トップページの世界観と情報設計を固める
2. 本人要望に沿うレイアウトへ寄せる
3. 書きたい内容をセクション単位で配置する
4. SNS、更新欄、ガイドラインなど補助導線を整える
5. モバイル表示、余白、動き、視認性を調整する

## 7. いまの作業ルール

- 本人要望の意図を残す
- ただし見づらさや使いづらさはそのまま再現しない
- 実装上の判断は、完成度が高くなる方向を優先する
- 後から本人確認がしやすいよう、仮置き箇所は docs に残す

## 8. 未確定情報

次の要素は、後から本人確認または素材差し替えが必要になる可能性が高い。

- 右側に書かれている各項目の正確な文言
- 正式なプロフィール文
- SNS の本 URL
- ガイドライン文面
- Contact 導線
- 掲載する画像やビジュアル素材の最終版
- タグ名の正式表記

## 9. このメモの使い方

- 画像の内容をそのまま貼り写すためのメモではなく、実装判断の基準として使う
- `design-spec-v0.1.md` の補助資料として扱う
- 今後、画像右側の内容を正確に転記できたら、このファイルに追記して更新する
